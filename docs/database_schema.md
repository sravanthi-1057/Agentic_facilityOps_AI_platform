# Database Architecture & Schema Documentation
## Milestone 1 (Energy Intelligence) & Milestone 2 (Predictive Maintenance)

The **Agentic FacilityOps AI Platform** utilizes a hybrid dual-database architecture:
1. **Relational Database (MySQL / SQLite Fallback)**: Stores structured facility registries, sub-meters, equipment assets, physical sensor readings, health logs, maintenance work orders, failure predictions, energy usage, and alerts.
2. **Document Database (MongoDB / Local DocStore Fallback)**: Stores raw semi-structured IoT sensor events, agent state snapshots, and LangGraph workflow execution traces.

---

## 1. MySQL Relational Schema

### A. Core Facility Hierarchy

#### `facilities` Table
Stores enterprise buildings and campus properties.
| Column | Type | Constraints | Description |
|---|---|---|---|
| `facility_id` | `VARCHAR(50)` | Primary Key, Index | Unique facility identifier (e.g., `FAC-001`) |
| `facility_name` | `VARCHAR(100)` | Not Null | Display name of the facility |
| `facility_type` | `VARCHAR(50)` | Not Null | Type (e.g. Commercial Office, R&D Lab) |
| `location` | `VARCHAR(150)` | Not Null | Campus or geographic location |

#### `energy_meters` Table (Milestone 1)
Stores sub-meters installed across facility floors.
| Column | Type | Constraints | Description |
|---|---|---|---|
| `meter_id` | `VARCHAR(50)` | Primary Key, Index | Unique meter identifier (e.g. `MTR-001-FL1-MAIN`) |
| `facility_id` | `VARCHAR(50)` | Foreign Key -> `facilities.facility_id` | Associated facility |
| `floor` | `VARCHAR(20)` | Not Null, Index | Floor level (e.g. `Floor 1`) |
| `meter_type` | `VARCHAR(50)` | Not Null | Main Smart Meter, Sub-Meter, etc. |
| `status` | `VARCHAR(20)` | Not Null, Default `ACTIVE` | Operational status (`ACTIVE`, `MAINTENANCE`) |

#### `energy_usage` Table (Milestone 1)
Granular time-series consumption records.
| Column | Type | Constraints | Description |
|---|---|---|---|
| `energy_id` | `INT` | Primary Key, Auto Increment | Unique record ID |
| `meter_id` | `VARCHAR(50)` | Foreign Key -> `energy_meters.meter_id` | Sensor / Meter ID |
| `timestamp` | `DATETIME` | Not Null, Index | Measurement timestamp (hourly intervals) |
| `electricity_usage` | `FLOAT` | Not Null | Total electricity consumed (kWh) |
| `water_usage` | `FLOAT` | Not Null | Facility water draw (Litres) |
| `hvac_usage` | `FLOAT` | Not Null | Cooling and ventilation load (kWh) |
| `lighting_usage` | `FLOAT` | Not Null | Fixture and lighting circuits (kWh) |
| `equipment_usage` | `FLOAT` | Not Null | Lab, IT, and plug load draw (kWh) |
| `temperature` | `FLOAT` | Not Null | Ambient outdoor temperature (°C) |

#### `energy_alerts` & `energy_recommendations` Tables (Milestone 1)
Stores energy anomalies flagged by Isolation Forest and prescriptive recommendations generated by the LangGraph Energy Agent.

### B. Predictive Maintenance Schema (Milestone 2)

#### `assets` Table
Master registry for facility equipment across chillers, AHUs, cooling towers, pumps, motors, generators, elevators, and electrical panels.
| Column | Type | Constraints | Description |
|---|---|---|---|
| `asset_id` | `VARCHAR(50)` | Primary Key, Index | Unique asset identifier (e.g., `AST-001-CHL-01`) |
| `asset_name` | `VARCHAR(100)` | Not Null | Equipment name (e.g., `Chilled Water Centrifugal Chiller 1`) |
| `asset_type` | `VARCHAR(50)` | Not Null, Index | `Chiller`, `AHU`, `Cooling Tower`, `Pump`, `Motor`, `Generator`, `Elevator`, `Electrical Panel` |
| `facility_id` | `VARCHAR(50)` | Foreign Key -> `facilities.facility_id` | Associated facility |
| `floor` | `VARCHAR(20)` | Not Null, Index | Floor / Location (e.g., `Basement`, `Rooftop`, `Floor 2`) |
| `installation_date` | `DATETIME` | Not Null | Commissioning date |
| `last_maintenance_date`| `DATETIME` | Not Null | Date of most recent service / overhaul |
| `next_scheduled_maintenance` | `DATETIME` | Nullable | Planned preventive maintenance target |
| `operational_status` | `VARCHAR(20)` | Not Null, Default `Normal` | `Normal`, `Warning`, `Degraded`, `Critical`, `Offline` |
| `health_score` | `FLOAT` | Not Null, Default `100.0` | Comprehensive equipment health score (0–100) |
| `failure_risk` | `FLOAT` | Not Null, Default `0.0` | Predicted failure risk percentage (0–100%) |
| `maintenance_priority` | `VARCHAR(20)`| Not Null, Default `Low` | `Critical`, `High`, `Medium`, `Low` |
| `runtime_hours` | `FLOAT` | Not Null, Default `0.0` | Cumulative operating hours |
| `asset_age_years` | `FLOAT` | Not Null, Default `1.0` | Operational age computed from installation |
| `updated_at` | `DATETIME` | Not Null | Timestamp of last health/telemetry calculation |

#### `asset_sensor_readings` Table
Real-time physical telemetry stream from IoT sensors installed on equipment.
| Column | Type | Constraints | Description |
|---|---|---|---|
| `reading_id` | `INT` | Primary Key, Auto Increment | Unique reading sequence ID |
| `asset_id` | `VARCHAR(50)` | Foreign Key -> `assets.asset_id` | Equipment asset ID |
| `timestamp` | `DATETIME` | Not Null, Index | Reading collection timestamp |
| `temperature` | `FLOAT` | Not Null | Operating / Bearing temperature (°C) |
| `vibration` | `FLOAT` | Not Null | Velocity RMS vibration (mm/s, ISO 10816) |
| `pressure` | `FLOAT` | Not Null | Operating suction/discharge/oil pressure (PSI) |
| `power_consumption`| `FLOAT` | Not Null | Active electrical load draw (kW) |
| `runtime_hours` | `FLOAT` | Not Null | Cumulative runtime at timestamp |
| `is_anomaly` | `BOOLEAN` | Not Null, Default `False` | True if reading violates safe operational envelopes |
| `anomaly_reason` | `VARCHAR(255)` | Nullable | Specific diagnostic explanation of anomaly |

*Composite Index*: `idx_asset_reading_ts (asset_id, timestamp)`

#### `asset_health_history` Table
Historical trend of equipment health scores and contributing factor deductions.
| Column | Type | Constraints | Description |
|---|---|---|---|
| `history_id` | `INT` | Primary Key, Auto Increment | Unique record ID |
| `asset_id` | `VARCHAR(50)` | Foreign Key -> `assets.asset_id` | Associated asset |
| `timestamp` | `DATETIME` | Not Null, Index | Historical score snapshot timestamp |
| `health_score` | `FLOAT` | Not Null | Health score (0–100) |
| `failure_risk` | `FLOAT` | Not Null | Failure risk percentage (0–100%) |
| `contributing_factors` | `TEXT` | Nullable (JSON) | Contributing penalty breakdown (temperature, vibration, pressure, runtime, age) |

#### `maintenance_alerts` Table
Equipment alerts generated when conditions breach safety thresholds or failure risk is high.
| Column | Type | Constraints | Description |
|---|---|---|---|
| `alert_id` | `INT` | Primary Key, Auto Increment | Unique maintenance alert ID |
| `asset_id` | `VARCHAR(50)` | Foreign Key -> `assets.asset_id` | Target asset |
| `facility_id` | `VARCHAR(50)` | Foreign Key -> `facilities.facility_id` | Facility reference |
| `severity` | `VARCHAR(20)` | Not Null, Index | `Critical`, `High`, `Medium`, `Low` |
| `title` | `VARCHAR(150)` | Not Null | Short alert title |
| `description` | `TEXT` | Not Null | Diagnostic details & recommended inspection |
| `status` | `VARCHAR(20)` | Not Null, Default `New` | `New`, `Acknowledged`, `Resolved` |
| `temperature` | `FLOAT` | Nullable | Reading at time of alert (°C) |
| `vibration` | `FLOAT` | Nullable | Reading at time of alert (mm/s) |
| `pressure` | `FLOAT` | Nullable | Reading at time of alert (PSI) |
| `created_at` | `DATETIME` | Not Null | Alert generation timestamp |
| `acknowledged_at` | `DATETIME` | Nullable | Acknowledgment timestamp |
| `resolved_at` | `DATETIME` | Nullable | Resolution timestamp |

#### `maintenance_schedules` Table (Work Orders)
Track planned and dispatched maintenance work orders.
| Column | Type | Constraints | Description |
|---|---|---|---|
| `id` | `INT` | Primary Key, Auto Increment | Internal sequence ID |
| `schedule_id` | `VARCHAR(50)` | Unique, Not Null | Public Work Order code (e.g., `WO-202611-0001`) |
| `asset_id` | `VARCHAR(50)` | Foreign Key -> `assets.asset_id` | Asset under service |
| `title` | `VARCHAR(150)` | Not Null | Work order title |
| `description` | `TEXT` | Not Null | Detailed scope of work |
| `scheduled_date` | `DATETIME` | Not Null, Index | Planned execution date |
| `completed_date` | `DATETIME` | Nullable | Sign-off timestamp |
| `status` | `VARCHAR(20)` | Not Null, Default `Scheduled` | `Scheduled`, `In Progress`, `Completed`, `Overdue` |
| `priority` | `VARCHAR(20)` | Not Null, Default `Medium` | `Critical`, `High`, `Medium`, `Low` |
| `assigned_technician`| `VARCHAR(100)`| Nullable | Certified specialist assigned to order |
| `estimated_duration_hours`| `FLOAT` | Nullable | Planned labor hours |
| `actual_duration_hours` | `FLOAT` | Nullable | Actual labor logged |
| `cost_estimate` | `FLOAT` | Nullable | Projected parts + labor cost ($) |
| `notes` | `TEXT` | Nullable | Technician field notes and close-out sign-off |
| `created_at` | `DATETIME` | Not Null | Creation timestamp |

#### `maintenance_predictions` Table
Predictive failure analysis and prescriptive actions synthesized by the Maintenance Agent.
| Column | Type | Constraints | Description |
|---|---|---|---|
| `prediction_id` | `INT` | Primary Key, Auto Increment | Unique record ID |
| `asset_id` | `VARCHAR(50)` | Foreign Key -> `assets.asset_id` | Asset predicted |
| `failure_risk` | `FLOAT` | Not Null | Calculated failure risk percentage (0–100%) |
| `risk_level` | `VARCHAR(20)` | Not Null, Index | `Critical`, `High`, `Medium`, `Low` |
| `estimated_days_to_failure` | `INT` | Not Null | Remaining Useful Life (RUL) in days |
| `recommendation` | `TEXT` | Not Null | Prescriptive maintenance intervention |
| `reason` | `TEXT` | Not Null | Engineering diagnostic reason |
| `abnormal_readings` | `TEXT` | Nullable (JSON) | Specific physical parameters triggering risk |
| `created_at` | `DATETIME` | Not Null | Prediction snapshot timestamp |
